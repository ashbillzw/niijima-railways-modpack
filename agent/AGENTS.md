# Agent 工作规则

更新日期：2026-10-11。面向 AshBill 的新岛铁道整合包工作。

本文件由原工作目录 AGENTS.md、仓库 agent.md 的视频规则及用户已确认的协作约定合并整理。规则按【通用规则】和【本项目规则】区分；当前任务状态与具体技术数据另见仓库 agent/handoff.md、agent/todo-list.md 和专题文档。

## 通用规则

### 交互与规则维护

- 用户询问读音时，默认回答日语读音；除非用户明确另有说明，不主动补充普通话等其他语言的读音。（2026-10-13 用户确认）

- 使用中文清楚说明已完成的工作、证据、待办和限制。优先使用 Codex 的选项卡／选择题机制进行有限选项的澄清和确认，并打开相关文件或 diff 供审阅。
- 发出选项卡后给用户充分阅读和回复时间；需要其决定的工作保持等待，不因暂未回复自动选项、视为同意或开始依赖该决定的操作。
- 收到可能长期适用的新指令时，用选项卡确认是否作为长期规则；确认后写入适当规则文档。用户已明确要求记录或整理规则时直接执行，不重复询问相同授权。单次任务参数不能擅自推广为永久规则。
- 维护规则时同步本机副本和仓库副本；其他机器的副本需在拉取后比较更新，不盲目覆盖其额外规则。使用日期与具体证据处理新旧结论，不仅按文件时间选择。

### Git 提交与远端操作

- 开工先检查工作区、当前分支与上游，保留已有改动；不把未提交、已提交未推送、远端已有提交混为一谈。
- 适合提交时按功能和依赖关系分组，展示 diff、说明验证情况，并通过选项卡取得提交许可。删除旧资源及其替代引用等相互依赖的修改应放在同一提交，避免中间提交缺少必要内容。
- 提交前参考近期 commit message 风格；有 gitmoji 时沿用分类，必要时参考 gitmoji.dev。
- 提交身份：author 为 `chatgpt-codex-astra <me@ashbill.com>`，committer 为 `AshBill <me@ashbill.com>`。身份可通过命令级环境变量指定，不因此修改全局 Git 身份。
- **agent 不执行 push，也不执行其他改变远端状态的操作；由用户手动执行。** 本地 commit 不等于上传或部署。用户授权的 fetch／pull 可获取远端更新。

### 多机器同步与冲突处理

- 用户要求同步合并时，先梳理本地未提交工作；成熟的改动优先分类展示并获准 commit，再 fetch，检查双方独有提交，再 merge。临时草稿可另议暂存；仓库外备份仅作为额外保障，不默认用 stash／恢复替代提交历史。
- 合并停在最终提交前供审阅。冲突按文件和冲突块逐项展示：共同基线、双方意图、建议方案；等用户确认后处理，不能整批默选 ours 或 theirs。
- 遇到性质完全一致的多处冲突，先说明样例和适用范围，询问本次后续同类型能否同样处理；用户同意后批量应用，例外再次讨论。这不是跨任务的永久冲突裁决。
- 自动合并也检查语义矛盾，例如已实现代码与“尚未实现”文档并存、旧目录规则与新结构冲突；实质行为差异单独讨论。
- 完成后检查冲突标记、格式及适用验证，展示汇总 diff，确认后创建合并提交。报告提交位置、工作区状态及与已获取上游的 ahead／behind，提醒用户自行 push；不把缓存的远端跟踪状态当作刚查询过的云端状态。

### 下载、验证与交接

- 常规使用 PATH 上的 7z 打包时，信任其基本压缩操作，以退出码及成功输出判断完成；不额外执行 ZIP 完整性测试、解压比对或逐文件哈希检查。仅在报错、有具体异常证据或用户明确要求验证时追加针对性检查。（2026-10-14 用户要求）

- 搭建测试实例等较大验证工程前，先提交包含下载内容与来源、运行方式、磁盘与具体路径、预计磁盘/内存占用及清理办法的计划，获用户批准后执行；不得将一般验证请求直接扩大为此类工程。（2026-10-12 用户确认）

- 本机使用全局 proxy。下载明显过慢或出错时，不反复重试；给出准确链接、版本、文件名及建议存放目录，让用户通过更快的代理获取，再继续本地验证。权限阻止与真实网络失败应区分处理。
- 不默认给 yt-dlp 添加 cookies；需要认证时按当前任务单独处理。凭据、cookies 和令牌不得写入仓库或交接报告。
- 区分“本地处理完成”“静态检查通过”“实际运行验证通过”“已部署上线”。没有证据不宣称后续状态；后台进程已启动不等于已完成。
- 对未来 agent 有用的结论必须在任务结束前写入仓库合适的专题文档或 handoff，不只留在聊天或本机日志。记录日期、适用条件、验证结果、路径和剩余事项；过时记录注明范围与替代结论。

## 本项目规则

- 本机仓库：`D:\mydata\Repositories\niijima-railways-modpack`；独立工作目录：`D:\mydata\Agents\Minecraft相关`。换机器后定位实际 checkout 和工作目录，不假定这些路径存在。
- 先读仓库 `agent/AGENTS.md`、`agent/handoff.md`、`agent/todo-list.md`，再按任务读专题文档。维护说明和任务记录统一放 `agent/`；大体积素材、临时日志、测试实例及备份放仓库外工作目录，除非用户明确指定入库。
- 本文件保存规则，handoff 保存接手方法与关键交接，todo 保存当前任务状态，专题保存技术细节。与用户探讨形成的整合包制作流程应落盘，避免只存在于对话。

### 模组和索引维护

- 在增删、升级、降级模组，查询兼容版本，编辑或检查 `modrinth.index.json`，以及验证更新或对比 PCL 结果前，先读仓库 `agent/整合包更新流程.md`；本机同步副本为工作目录 `流程文档/整合包更新流程.md`。
- 遵循其中 API 查询、兼容版本筛选、字段映射、排序、下载限制及验证交接约定。历史版本和数量仅作案例，实际更新重新核查。不得为补元数据擅自完整下载模组 JAR。
- 路径、SHA-1、SHA-512、下载地址和字节大小必须对应同一目标文件；保留已确认的禁用状态与包服差异，不因某版本较新而擅自升级。读取最新候选取舍和测试状态，不能把建议视为安装授权。
- 用户明确要求“仅测试”时，在独立工作目录生成临时副本，不修改原项目、不 commit；测试通过不等于获准应用。

### 新增模组候选清单展示格式（2026-10-12 用户确认）

- 生成或重新展示待新增模组清单时，沿用用户指定的完整逐项表格格式，不将多个模组合并进同一行。
- 开头说明当前具名候选数量与待选型需求数量，并说明“候选不代表已经决定安装”；数量随最新状态计算，不固定为历史的 20 项与 2 项。
- 具名候选按类别分组，使用三列：`编号 | 候选 Mod | 当前需要讨论的重点`。每个模组单独一行，编号跨类别连续；分类可沿用基础机制、地图、食物与生活、机械动力与交通、建筑与展示、服务器工具，并按实际内容调整。
- 尚未确定具体模组的需求另用两列表格：`需求 | 待讨论内容`，例如游戏内语音、TPS HUD，不混入具名候选编号。
- 已完成或已加入、暂缓、倾向不加入及忽略的旧计划单独列出，保留其最新决定与测试状态，不重复计入当前待新增候选。

### 服务端与共用资源

- YSM 文件编号采用四位大写十六进制 `0000–FFFF`，文件名为 `HHHH_名称`；前三位为系列编号、末位为系列内序号，超过 16 项可向空闲后续段溢出。2026-10-14 初始首系列之前及系列之间均预留 31–63 个空系列编号，固定分配表见 YSM 专题。以后新增使用空位，不重新随机或顺延已有 ID；溢出前检查段占用，名字部分也不可随意改动。
- 维护前读 `agent/YSM统计（旧 服务端配置差异）.md`、`agent/服务端更新器.md`。`server/` 当前是 shared 共享层和两服差异层，不是完整运行实例。
- 共用 KJS／YSM 从包内资源维护，通过 shared 的 `.ablink` 引用；额外模型和单服差异按专题规则保留。实例配置与实际存档 `serverconfig` 按适用范围同步；改 `defaultconfigs` 不等于改已有世界。
- 共用模组位于 `server/shared/mods/`，单服专用内容留在各服 `mods/`。更新器不解析包索引，修改索引时必须检查相应引用或 JAR，避免旧新版同时存在。
- `.ablink` 目标名由去掉扩展名决定；内容为下载直链或分支引用。优先 `__master__` 是既有维护约定，不代表当前 master 已含开发分支内容；核对引用来源和展开结果后才判断可部署。
- 现有删除表明确重建两服 `mods`、`kubejs`、`config/yes_steve_model/custom`。执行前停服、整服 snapshot，确认额外资源纳入更新源；每个删除路径现场确认。不要把这个例外扩大到整个 config、世界数据或其他目录。没有自动回滚，实际部署由用户手动执行。
- YSM 默认角色配置使用实际模型 ID，不凭显示名猜测。琴音原 ID 经玩家存档核对为 `藤田ことね.ysm`；2026-10-14 本地资源编号后为 `0230_藤田ことね.ysm`，贴图仍为 `ktn`，部署状态见 YSM 专题；扩展名不可漏写。出现问题时核对实际实例、存档配置与日志。

### 背景视频

- “标准剪辑 A”（2026-10-13 用户定义）：最终保留片段开头 3 秒音频渐入、画面渐明，末尾 3 秒音频渐出、画面渐暗；裁剪范围另按本次要求。仅在用户指定时套用。

- 文件名沿用 `bg-video-编号-曲名.mp4`：编号按现有补零形式，曲名为连续小写英文或罗马字，不加空格或词间连字符。
- 交付前核对最新目录和已分配但未上线的编号，从最大已用编号顺延，不重用、不覆盖。最新编号记录在专题文档，不固化在规则里。
