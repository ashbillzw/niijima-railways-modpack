# 服务端更新器

人工低频执行。操作前自行停止服务器并完成整服 snapshot；测试时直接使用真实服务器的副本。当前尚未执行 GitHub 下载和实际部署。

## 目录

```text
server/
  delete.json
  shared/
    kubejs.ablink
    config/
      yes_steve_model.ablink
      yes_steve_model/custom/tsukimura_temari.ysm
    mods/                            两服共同模组的下载引用或实际 JAR
  create-cn/
    config/
    create-cn_world/serverconfig/
    server.properties
    mods/                            主服额外模组
  train-cn/
    config/
    train-cn_world/serverconfig/
    server.properties
    mods/                            创造服额外模组
updater/
  update.py                          此目录唯一纳入 Git 的文件
  create-cn/                         用户复制来的主服实例
  train-cn/                          用户复制来的创造服实例
```

`server/` 是更新源，`updater/` 中的实例是更新目标。配置继续独立保存三份。KubeJS、YSM 共同内容引用包内文件，月村手毬作为服务器额外模型保留。

## ablink 规则（2026-10-07 最终约定）

| 源文件 | 内容 | 写入服务器的结果 |
| --- | --- | --- |
| `mods/example.jar.ablink` | 一行 HTTP/HTTPS 文件直链 | 下载为 `mods/example.jar` |
| `kubejs.ablink` | `__master__` | 从 master 的 `pack/overrides/kubejs` 复制目录 |
| `config/example.cfg.ablink` | `__master__` | 从 master 的 `pack/overrides/config/example.cfg` 复制文件 |
| `config/example.cfg.ablink` | `__agent-dev-1.6__` | 从 agent-dev-1.6 的同一路径复制文件 |
| `mods/example.jar` | 实际 JAR | 原样复制为 `mods/example.jar` |

去掉 `.ablink` 就是目标名称，不再使用文件名前缀。去掉内容首尾空白后，以 `http://` 或 `https://` 开头时下载这个文件；否则将内容解析为分支名，从该分支的 `pack/overrides/` 获取目标相对路径对应的文件或目录。分支名可写为 `__master__`、`__agent-dev-1.6__`，也接受不带双下划线的名字；空内容报错。维护时优先写 `__master__`，但脚本不强制使用 master。例如 `server/shared/config/example.cfg.ablink` 内容为 `__master__` 时，对应 `https://github.com/ashbillzw/niijima-railways-modpack/blob/master/pack/overrides/config/example.cfg`；实际文件内容通过 raw 地址读取。URL 使用标准正斜杠形式和文件直链，不使用返回 HTML 的网页地址。

先展开引用，再覆盖同名本地文件或目录；共享层先于专属层。目录合并，不因引用源缺少某个文件而删除目标文件。标记本身不写入服务器。不允许空目标名，也不支持引用源再嵌套 `.ablink`。

目标文件名只由 `.ablink` 的名字决定，与 URL 末尾的名字无关。此规则适用于任意文件，不为 JAR、JSON 等文件类型增加特殊解析行为。

更新器不读取 `modrinth.index.json`，也没有模组排除、重命名表。每个模组是否安装、安装成什么文件名，直接由 `mods/` 中的实际文件或引用决定。维护要求见制作工作流的“服务端 ablink 同步”。

2026-10-07 整理结果：shared 共 88 个模组（87 个下载引用、1 个轨道地图补丁 JAR）；主服另有 8 个（5 个引用、3 个 JAR），创造服另有 1 个引用。最终仍是主服 96 个、创造服 89 个。主服 DH 启用、创造服不装；TrainResync 主服 d、创造服 a 保持不变，等待 g 发布。

## 执行

将改动上传到 GitHub，再把服务器副本放到 `updater` 下，在该目录运行：

```sh
python update.py
# 仅更新主服，并从开发分支获取服务端分包：
python update.py --server create-cn --branch agent-dev-1.6
```

`--server` 默认为 `all`，也可选 `create-cn` 或 `train-cn`；`--branch` 默认为 `master`，只控制 `server/` 分包和删除表的来源。各 `.ablink` 的分支从文件内容读取，独立于分包来源，因此允许从 A 分支读取分包、从 B 分支引用文件。每个实际使用的分支在一次运行中固定到 commit，外部 URL 按标记内容下载，同一 URL 成功下载后在本次运行中复用。下载完成前不修改实例。

网络连接及读取超时为 30 秒；网络请求失败（包括 HTTP 错误或传输中断）后固定等待 30 秒重试，不使用指数退避、不限制重试次数，可用 Ctrl+C 终止。适用于 GitHub API 和文件下载；下载中途失败时从头重下该文件。格式、路径或本地磁盘错误不按网络重试处理。

实例根目录为脚本所在目录 `.`，布局是 `update.py` 与 `create-cn/`、`train-cn/` 同级。所选实例目录应已存在。下载与展开使用同目录下的 `download-随机字符/`，启动后打印完整路径；`source/` 缓存分包、`branch-*` 缓存其他分支、`external/` 缓存 URL 文件、`create-cn/` 和 `train-cn/` 保存待写入结果。全部所选实例准备完成后才开始删除与覆盖，退出时清理临时目录。

即使当前在开发分支维护引用，也优先写 `__master__`，以之后合入的 master 为基准；尚未合并的内容不会被 `__master__` 读到。

要求 Python 3.9+，仅使用标准库。Ubuntu 通常用 `python3`。目标始终相对于脚本所在目录，与启动时工作目录无关。保持文件名大小写一致，并避免 Windows 不支持的文件名；不接受符号链接或 junction。没有 dry-run 模式、自动备份或自动回滚。

## 删除

`delete.json` 有 `shared`、`create-cn`、`train-cn` 三个路径数组，相对于各服实例根目录，不支持通配符。按用户确认，两服均删除后重建 `mods`、`kubejs`、`config/yes_steve_model/custom`；其他路径只更新覆盖。

准备好全部所选服务器的新文件后，逐项删除，再写入合并后的文件。每项实际删除前显示完整路径并询问 `y/n`，递归删除整个目录只问一次。`n` 立即终止脚本，已完成操作不回滚；其他输入重新询问。不存在的路径打印 NOTE 并继续下一条。

删除表格式校验要求恰好有 `shared`、`create-cn`、`train-cn` 三个数组，未使用的数组可为空；即使只选择一服，也不能省略其他字段。

按最终规则核对：shared 共 91 个源文件，主服差异层 106 个，创造服差异层 76 个；其中 93 个为 URL 引用、2 个为 `__master__` 目录引用。旧前缀标记及模组索引、排除、重命名规则文件均已移除。删除表仅保留上述三项目录，两服各自的附加删除数组为空。

以本地 pack 作为未来合入 master 后的内容核对，展开后主服 314 个文件、创造服 284 个文件，与重构前的路径及内容一致（KubeJS 忽略 LF/CRLF 差异）。这不表示当前远端 master 已含这些内容；GitHub 下载、真实服务器副本和 Ubuntu 运行验证待用户准备环境后进行。
