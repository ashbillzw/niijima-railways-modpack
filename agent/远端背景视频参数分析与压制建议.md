### YouTube 只返回 360p：已验证的排障方法

2026-10-10，视频 `https://www.youtube.com/watch?v=_m8_jvN41UM` 在 yt-dlp 默认客户端下只返回格式 `18`（640×360），日志提示部分格式缺少 URL，并提到 SABR；不带 cookies 或切换到 `android_vr` 又遇到登录验证提示。这说明此次提取未取得高清流，不说明原视频只有 360p；更改 `-f best` 或直接放大画面不能解决流缺失。

**成功方法：使用 `web_safari` 客户端取得 HLS 流。** 当次格式列表中 `95` 为 720p、`96` 为 1080p，下载 `96` 后经 ffprobe 确认为 1920×1080、30000/1001 fps、H.264 + AAC。实际使用 yt-dlp **2026.08.19**，已有配置启用 `--js-runtimes node` 和用户自己的 `--cookies` 文件；网络经本机代理 `127.0.0.1:10808`。无需为复现本次结果先安装 PO Token 插件。

```powershell
# 先检查格式；格式编号随视频或站点变化，不要盲目沿用 96。
yt-dlp --no-playlist --extractor-args "youtube:player_client=web_safari" -F "https://www.youtube.com/watch?v=_m8_jvN41UM"

# 本次成功命令。继承本机已有 cookies、Node 和网络配置。
yt-dlp --no-playlist --extractor-args "youtube:player_client=web_safari" -f 96 --concurrent-fragments 8 --write-info-json -o "C:/mydata/Agents/Codex-CreateTrainResync/视频输出/原始下载/%(id)s-1080p.%(ext)s" "https://www.youtube.com/watch?v=_m8_jvN41UM"

# 下载后核对实际分辨率和音轨，而不是仅看输出文件名。
ffprobe -v error -show_entries "stream=codec_name,width,height,r_frame_rate:format=duration,size" -of json "input.mp4"
```

迁移到其他机器时应配置有效的本机 cookies、JS 运行时和网络；不要假定上述代理存在，也不要在仓库中保存 cookies 内容或临时签名下载 URL。本次 HLS 共 39 个分片，传输约 6 分 30 秒，平均 255.81 KiB/s。下载过慢应通知用户；必须等下载完成并核对源文件后再宣布素材就绪，不能把后台进程仍在运行当作交付完成。

该方法只承诺上述实测条件，YouTube 客户端行为可能变化。若以后失效，先看日志和 `-F` 的实际格式，再核对工具版本、会话及官方文档：[SABR 问题记录](https://github.com/yt-dlp/yt-dlp/issues/12482)、[客户端与 PO Token 说明](https://github.com/yt-dlp/yt-dlp/wiki/PO-Token-Guide)。

### 新视频的音量处理与验收

1. 测量源音轨的综合响度、真峰值；`loudnorm` 用于分析时读取 **`input_i`、`input_tp`、`input_lra`**，不是 `output_*`。下面分析命令的 `I=-17:TP=-3` 不会改写输入文件，也不代表它已被归一化。
2. 优先以固定增益保持原动态：`增益 dB = -17 - 源综合响度 LUFS`，在音频编码前使用 `volume=增益dB`。先检查预计峰值是否有余量；若固定增益会造成峰值过高，应另行选择限峰或经测量的两遍 `loudnorm`，不能只顾 LUFS 而造成削波。
3. AAC 重编码和重采样会改变响度、峰值，必须对**最终文件完整复测**。以约 -17 LUFS 匹配现有库，不要求所有曲目峰值相同；必要时修正增益并重编码音频。峰值需保留余量，本次两份成品均低于 -2 dBTP；这是本次验收结果，不是已追溯到的历史统一限幅参数。
4. 核对视频与音频规格，完整解码检查；记录源分辨率、增益和成品实测值。已有合格视频流只改音量时可 `-c:v copy`，音频从高质量下载源重新编码。

```powershell
# 完整音轨分析；不加 -t，不修改输入。
ffmpeg -hide_banner -nostdin -nostats -i "input.mp4" -map 0:a:0 -vn -af "loudnorm=I=-17:TP=-3:LRA=11:print_format=json" -f null NUL

# 独立复核；该滤镜的 True peak 段有时标成 dBFS，含义仍是真峰值。
ffmpeg -hide_banner -nostdin -nostats -i "output.mp4" -map 0:a:0 -vn -af "ebur128=peak=true" -f null NUL

# 在下方历史压制命令中增加相应 -af，例如本次 YouTube 源衰减 2.69 dB：
# -af "volume=-2.69dB"
# 此增益只适用于本次实测源，不能作为其他歌曲的通用值。

# 完整解码验收。
ffmpeg -v error -nostdin -xerror -i "output.mp4" -map 0:v:0 -map 0:a:0 -f null NUL
```

## 开头黑幕的判定口径

只取**从时间戳 0 开始的第一段连续黑区间**，不把后面的暗场相加。首次扫描各视频前 30 秒，并复查前 4 秒；所有开头黑区间均在 3 秒以内结束。30 fps 下，边界的时间粒度约为 0.033 秒。

- 近黑：`blackdetect=d=0.01:pix_th=0.10:pic_th=0.98`。
- 严格黑阈值：`blackdetect=d=0.01:pix_th=0.02:pic_th=0.98`。

二者均要求至少 98% 像素满足黑色亮度阈值。对这些 limited-range 8-bit 视频，亮度阈值分别约为 37.9 和 20.4（黑电平为 16）。严格阈值仍允许少量亮点和近黑像素，并不表示每个像素都为纯黑。[FFmpeg blackdetect 文档](https://ffmpeg.org/ffmpeg-filters.html#blackdetect)

例如 09 的近黑区间为 2.933 秒，但严格阈值只有 0.500 秒，因此不能直接描述为“前 2.933 秒全是纯黑”。05 在 1.900–4.900 秒又出现一段近黑区间，属于后续暗场，不计入开头黑幕。

```text
rc=crf crf=28.0 vbv-maxrate=2000 vbv-bufsize=4000

ctu=64 me=1 subme=2 rd=3 rdoq-level=0
open-gop min-keyint=25 keyint=250 scenecut=40
```

流标签记录 `Lavc61.11.100 libx265`，容器记录 `Lavf61.5.101`。

`ref=3`、`b-adapt=2`、`rc-lookahead=20` 等组合与 x265 的 **medium** preset 相符，因此原命令很可能采用默认 medium 或显式 `-preset medium`，也可能手动配置了等价参数。preset 名称本身不能由这些记录唯一确定。[x265 preset 参数表](https://x265.readthedocs.io/en/master/presets.html)

能够直接确认的是文件内记录的 CRF 和 VBV 参数；无法恢复原始输入、缩放算法、剪辑位置、淡入淡出、音量处理或完整历史命令。相同 CRF 不保证相同码率；VBV 约束还可能影响复杂片段的量化。[x265 码率控制说明](https://x265.readthedocs.io/en/master/cli.html#quality-rate-control-and-rate-distortion-options)

## 建议的 FFmpeg 命令

### 生成相同基本规格的背景视频

以下为 Windows PowerShell 写法，建议使用质量较高的原始素材。修改输入、输出路径后执行；`-n` 避免覆盖已有文件。反引号必须位于每行末尾，后面不能有空格。

```powershell
ffmpeg -hide_banner -n -i "input.mp4" `
  -map 0:v:0 -map 0:a:0 `
  -vf "scale=1280:720:force_original_aspect_ratio=decrease:force_divisible_by=2,pad=1280:720:(ow-iw)/2:(oh-ih)/2:black,setsar=1,fps=30" `
  -c:v libx265 -preset medium -crf 28 `
  -maxrate:v 2000k -bufsize:v 4000k `
  -pix_fmt yuv420p -tag:v hvc1 `
  -c:a aac -b:a 128k -ar 44100 -ac 2 `
  -movflags +faststart "output.mp4"
```

该命令适用于含音轨的常规 SDR 素材。按比例缩放并补黑边得到 1280×720，避免直接拉伸；16:9 素材通常不需要补边。HDR 输入需要另行设计色调映射，不能仅靠改为 `yuv420p` 转成正常 SDR。

CRF、VBV、编码格式、帧率及音频规格依据现有文件设置。`+faststart` 是面向远端 MP4 播放的额外建议，将索引移至文件前部；不据此声称原命令使用了该选项。`hvc1` 与现有文件一致，但实际播放能力仍需在目标播放器中验证。

不要为了凑出表中平均码率改用固定的 `-b:v`：同一套 CRF 参数会随素材复杂度产生不同文件大小。上述命令也不保证重现原文件的音量或字节内容。

### 开头黑幕与音量的处理

主命令保留素材已有开头，不主动插入黑幕。现有文件的检测结果不足以支持“统一补几秒黑幕”或“统一使用几秒 fade”的结论。

如后续制作规范明确要求**新增 1 秒黑幕，同时推迟音频 1 秒**，可以将主命令的 `-vf` 替换为以下内容，并添加对应 `-af`，其他编码参数保持相同：

```powershell
-vf "scale=1280:720:force_original_aspect_ratio=decrease:force_divisible_by=2,pad=1280:720:(ow-iw)/2:(oh-ih)/2:black,setsar=1,fps=30,tpad=start_duration=1:start_mode=add:color=black" `
-af "adelay=1000:all=1"
```

这会增加时长，且输入自身的黑幕仍会保留；并不保证检测到的总开头黑幕恰好为 1 秒。淡入则是另一种处理，例如 `fade=t=in:st=0:d=1` 会在原有时间线上渐亮，不等于新增 1 秒黑幕。

历史命令默认保持输入增益；**新制作应按上方当前基准测量并匹配约 -17 LUFS**。以下仅保留峰值调整的计算示例，不作为响度统一方法：若明确要以样本峰值调整音量，可先测量原素材峰值 P，再按 `目标峰值 - P` 得到 `volume` 的 dB 增益。例如输入峰值 -1 dBFS、目标 -3 dBFS，可添加 `-af "volume=-2dB"`。AAC 编码可能改变峰值，必须测量输出后复核。若同时使用延时，应合并为一个音频滤镜链，如 `-af "adelay=1000:all=1,volume=-2dB"`。曲目间听感一致以综合响度为依据，不能只看峰值。

## 复测命令与原始记录

以下命令用于单文件复测。音量分析不加 `-t`，遍历完整音轨；黑幕分析限定前 30 秒。

```powershell
ffprobe -v error -show_format -show_streams -of json "input.mp4"
ffmpeg -hide_banner -nostdin -i "input.mp4" -map 0:a:0 -vn -af volumedetect -f null NUL
ffmpeg -hide_banner -nostdin -i "input.mp4" -t 30 -map 0:v:0 -an -vf "blackdetect=d=0.01:pix_th=0.10:pic_th=0.98" -f null NUL
ffmpeg -hide_banner -nostdin -i "input.mp4" -t 30 -map 0:v:0 -an -vf "blackdetect=d=0.01:pix_th=0.02:pic_th=0.98" -f null NUL
```
