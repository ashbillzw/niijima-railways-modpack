## 每个模组的交付规则（2026-10-16 用户明确要求）

1. 后续一个模组一个模组推进。按优先级表从 ST001 开始，**每完成一个模组的当轮工作就停下来通知用户**；不因队列包含多项而自动连续处理。
2. 仅筛查时提供独立 Markdown 报告，列出检查范围、结果、潜在问题译文、证据、建议和待确认事项。区分明确错误、上下文待核实问题与纯措辞偏好。
3. 已有中文的模组也进行检查，不能把键覆盖率 100% 当作翻译质量合格。保留上游中文中合理的文风，不为了“改得更多”重写整套文本。
4. 遇到偏好类问题，展示具体例子；用户决定后记录选择、日期和适用范围。未答复不默认同意，不把单个术语选择推广到所有模组。
5. 如果实际生成了翻译，交付时展示 **10 条最具代表性且类型多样的译文**。覆盖不同物品类别、操作、说明、设置或提示等，不能用十种颜色的同一物品凑数。若实际改动不足十条，全部列出并说明数量，不杜撰改动。仅有建议稿时明确尚未应用。
6. 更新进度表与模组报告，记录已审查键／书页、补译与纠错数量、未解决项、下一步位置，以及静态检查和游戏验证各自状态。
7. 本目录保存所有汉化专题 Markdown；原始 JAR、导出数据和临时脚本留在仓库外 `C:/mydata/Agents/Codex-CreateTrainResync/lang-audit/`。重跑生成器不得覆盖人工偏好、进度或已确认结论；本机旧脚本的输出路径需先适配本目录。
