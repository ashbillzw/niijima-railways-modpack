## 范围与结论

基线：当前工作区 `pack/modrinth.index.json` 的 v1.6.0（Minecraft 1.20.1／Forge）及 `pack/overrides/mods`，不是前一轮 NF1.21.1 候选。共 **111 个模组文件条目：109 个索引条目 + 2 个直接内置 JAR**；110 个启用、1 个 Distant Horizons 禁用。文件条目不等于注册 mod ID 数；含 JAR 内嵌库。

全部文件已从本机 build/cache 或现有实例取得；109 个索引条目均核对大小和 SHA-1，内置 JAR 直接读取并记录 SHA-1。没有下载、更新、启动游戏或修改语言资源。包配置为 `lang:zh_cn`、`resourcePacks:[]`，包内无 resourcepacks 目录；已合并 KubeJS 语言覆盖及本机 MC1.20.1 资产索引 5 对应的原版简中。

- 启用条目中，**59 个 JAR 存在标准语言缺译候选**；按 JAR 归属计 3756 条，按全局 key 去重为 **3672 个键**。差异主要来自多个模组重复内嵌 DragonLib 等库。
- 另有 **517 条“中文值仍不含汉字”的复核候选**，不能全部算作漏译：其中包含名称、缩写、单位，但也确有整段英文和未翻译物品名。
- 缺译候选不等于运行时可见字符串数量：旧键、兼容其他未安装模组的内容、仅编辑器／配置界面使用的键都可能存在。全文本键和原文见附录。
- WorldEdit 的独立翻译系统、Konkrete 的 `.local`、Patchouli 书本和模型语言另列；不与标准语言键直接相加。

## 非标准文本与不能自动判定的内容

- **WorldEdit 7.2.15**：`lang/strings.json` 包含 417 条默认文本；包内未附中文翻译档，`default-locale=default`。本机实例 worldedit/assets 亦未发现现存文件。本次未验证其运行时翻译下载／加载行为，因此列为独立系统待核对，而不宣称官方没有中文。命令描述与反馈需要单独处理。
- **Konkrete 1.8.0**：内置 `assets/keksuccino/konkretelocals/en_us.local` 有 14 条常用界面文字（Width、Height、Choose File 等），未见 zh_cn.local；包内 config/konkrete/locals 只有英文。应按它自己的格式补译。
- **Patchouli**：扫描四个宿主模组中的 499 个 name/text/title 等字段。女仆餐厅书本位于 en_us 目录，但大部分引用已存在的中文语言键，不能判整本未汉化；其中 cook_maid.page_4 与 send_order.page_5 两个引用缺键。女仆仓管有 4 个英文字段在中文对应路径／页号位置不存在，可能是中英文版本结构不同，必须先对照整篇中文书页，不能直接认定漏译。模板里的 #output_desc/#power_cost 是变量，已排除。
- 内嵌可选资源包、女仆／YSM 模型语言发现 97 条无中文或非汉字候选，其中包括作者名／模组名；未证明这些可选内容在本包实际启用，不计入主统计。包内外置女仆模型语言、二进制 YSM 自定义模型、图片文字和光影包不属于本轮主统计，不能据此声称全界面已穷尽。
- **25 个 JAR 无标准 en_us 对象**。包括若干库／行为模组，也包括 TrainResync、WorldEdit、Konkrete。没有对所有 class 做完整反编译和调用路径追踪，硬编码菜单／聊天文本、自动生成配置名仍需运行或源码专项审计。TrainResync 本地源码可见直接构造中文提示的用法，因此没有 lang 文件并不等于全是英文。
- Create Framed 的 en_us／zh_cn JSON 带 `//` 注释；扫描时仅在字符串外去除注释后读取，未改原文件，也未验证游戏加载行为。MaidAddition 的 assets/ai/lang/zh_cn.json 实际为 AI 指令匹配数组，已识别并从普通语言统计排除，不是坏掉的翻译文件。

## 方法、边界与后续补译方式

- 读取标准 `assets/<namespace>/lang/en_us.json` 与 `zh_cn.json`，递归读取 META-INF/jarjar 与 META-INF/jars 的内嵌 JAR。全局 key 合并跨 namespace 的中文覆盖。存在多份同键翻译时，本轮按“至少存在一份非空覆盖”计覆盖，未模拟完整资源加载优先级，因此不是实际界面的精确快照。
- 排除英文源中的空白占位、已含汉字文本与明确注释键；不把 `${...}` 等纯插值引用作为未翻译英文。对仍无汉字的值保留复核候选，不自动翻译 ID、格式符、作者名或缩写。含中文但夹带未译英文的语义质量不在此自动统计能力内。
- 标准缺键是语言资源层面的证据。应优先抽样进游戏确认常用物品／界面，随后以 KubeJS assets 或独立资源包增量补译，保留 `%s`、`%1$s`、颜色符和插值引用；特殊系统按各自加载机制处理。当前仅授权扫描，尚未制作翻译。
- 所有 JAR 均成功打开，标准语言对象无未处理解析错误；统计对象与清单一一对应。没有进行游戏运行验证。

- **与现有风格对齐。** 翻译前参考本包定制译文、同模组已有译文，以及原版和相关模组的同类文本，整理共用术语与命名结构。可以参考其他已有译文，但需核对版本、实际含义和上下文，不能仅凭同名直接套用。引用外部译文时保留来源；大规模复用前核对许可。
- **物品名保持自然、紧凑、平行。** 沿用同类物品的修饰顺序、简称和词长，不机械补出“的”“含有”等说明性成分。例如用户假设 `super_fancy_blue_boat` 已译作“超炫酷蓝船”，则 `super_sweet_jam_bread` 应优先采用“超甜果酱面包”，而非“含有超级甜的果酱的面包”。此为风格示例，不是对实际物品含义的认定，也不是所有 `super` 一律译成“超”的固定映射。
- **先确认含义，再追求一致。** 结合英文显示名、物品用途、配方、同系列名称及必要的实际界面判断语义；注册 ID 仅作线索。简洁不能省略用于区别物品或操作的重要信息。按钮名、物品名、说明段落分别采用相应风格，不把说明文字都压缩成名词。
- **已有译文也要适度校对。** 扫描明显错字（如用户提到的“冰淇凌”类问题，通常规范写法为“冰淇淋”）、同一概念不同译法、同系列命名不一致、误译、英文残留和缺失关键信息。保留专有名称的例外；发现旧译错误时修正或列出有依据的建议，不为迎合旧译而复制错误。本节没有认定当前文件仍存在用户举例的那个错字。
- **校对范围以定向检查为主。** 对重复词、材料、颜色、食品类别、铁路术语和常用界面优先检查；不是承诺将全部既有中文逐句重新翻译。明确错误可按证据处理，涉及用户已定命名或有多种合理译法时集中列出少量争议项供决定。
- **保护技术结构。** 保留格式参数及序号、颜色码、换行、点击指令和 `${...}` 引用；不可把 ID、单位符号、模板变量或作者名误作普通语句翻译。完成后检查键覆盖、占位符、JSON／特殊格式及同类术语一致性，再抽样查看游戏内截断、换行和实际含义。
- **交接可持续维护。** 实施时在本专题或配套术语表记录确定的术语、例外、参考来源、旧译纠错及待确认事项，避免后续批次重新发明命名。生成脚本不得覆盖或丢失本节人工维护要求。
