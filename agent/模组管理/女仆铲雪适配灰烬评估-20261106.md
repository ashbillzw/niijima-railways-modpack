## 结论

不能仅加方块标签实现，但只需扩展现有铲雪任务的目标判定，改动范围小。建议在 TrainResync 中用一个 Mixin 扩展 `TaskSnow.canHarvest`，保留原结果，并额外接受 `supplementaries:ash`。沿用既有任务、寻路、方块破坏和拾取，不新增任务或重写 AI。

估计新增一个约 25–40 行的 Mixin 文件（含 import／注解），修改 Mixin 注册；若按现有整合包标记约定限制新功能，再调整现有 Mixin plugin 一处。合计约 2–3 个文件、几十行代码，具体以实施时的正式分支为准。目标可以按方块注册 ID 精确匹配，避免因引用灰烬类而增加缺失模组时的类加载问题。

## 代码依据

- 实际女仆 JAR 的 `TaskSnow.canHarvest` 只执行 `cropState.getBlock() instanceof SnowLayerBlock`，与本地源码一致，没有读取方块标签。`TaskSnow.harvest` 调用女仆通用 `destroyBlock`，没有把状态强转为雪或读取雪层属性。
- 实际 Supplementaries JAR 的 `AshLayerBlock` 继承 `FallingBlock`，不是 `SnowLayerBlock`。灰烬已在 `minecraft:mineable/shovel` 中；该标签不参与女仆的目标判定。
- `MaidFarmMoveTask.shouldMoveTo` 搜索时使用 `canHarvest`，`MaidFarmPlantTask.start` 到达后再次调用它并检查 `maid.canDestroyBlock`。因此只扩展这一入口便能覆盖目标搜索及实际收获；可达性、上方空间和破坏事件判断继续沿用现有逻辑。
- `EntityMaid.destroyBlock` 通过方块 loot table 计算掉落，先放入女仆可用背包，剩余物品落地，再更新方块并发送破坏事件。灰烬掉落表无铲子或附魔条件；1–7 层分别给对应数量，最后分支为 8 个灰烬。
- KubeJS 可以注册农业任务，但 `FarmTaskJS` 使用另一套周围搜索 AI；同 ID 注册还会向任务索引追加一项。为这一个判定替换或新增整个任务，比局部 Mixin 范围大，不建议作为最小方案。

## 继承原任务的行为与边界

- 持铲时一次清除该格的全部灰烬层，收取 1–8 个灰烬；成功破坏扣铲子 1 点耐久，按方块而非按层扣除。
- **不持铲时也会清除，但不掉落物品。** 这是原铲雪任务的现有行为。若希望灰烬必须持铲才能清理，需要用户另行确定这一行为差异，不能默认添加限制。
- 不使用灰烬的刷子逐层去除接口；不自动清除其他粉尘、沙子或所有可铲方块。
- 无需新增界面、任务图标、配置面板或异步任务。若未来确有多种清理对象，再考虑给这一判定增加专用标签；当前仅配置标签不会生效。

静态评估风险低，运行效果仍须验证：薄层／8层灰烬与雪混排、持铲及空手、背包容量、原有破坏限制和可达性。灰烬下落／叠层场景也需游戏观察。本轮没有启动游戏，也没有把实施或测试另增为待办。
