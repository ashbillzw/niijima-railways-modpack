# Server Shop：彩蛋商店构想

记录日期：2026-11-06。来源：AshBill 提出的 server shop command 想法。状态：稀有度概率与档内等概率规则已确认，彩蛋清单继续讨论；用户要求暂不实现，本轮只记录文档。

## 用户已提出的玩法

- 做一个服务器商店，玩家可以花**游戏内货币**购买彩蛋物品。
- 购买结果类似盲盒，不直接选定某一件具体物品。
- 参考初代《Love Live! 学园偶像祭》（SIF）的稀有度与劝诱概率。
- **先按照概率抽出稀有度，再从该稀有度对应的物品内容中抽取奖励。**
- **已确认四档概率：R 80%、SR 15%、SSR 4%、UR 1%。**
- **同一个稀有度里的物品先等概率抽取。**

这里的“彩蛋物品”尚未指定具体清单，不预设为强力装备、纯装饰品或已有模组的礼包。功能暂称 Server Shop；具体命令前缀、子命令和参数尚未确定，不能把这份记录视为已有命令接口。

## 初代 SIF 参考

参考对象是初代手机游戏 SIF，不是 SIF All Stars 或 SIF 2。以下概率分开注明卡池及时期，不能统称为整个初代运营期间始终不变的概率。

### 稀有度与经典特待生勧誘

完整常见稀有度顺序是 **N → R → SR → SSR → UR**，见[卡片分类资料](https://w.atwiki.jp/lovelive-sif/pages/34.html)。SSR 并非开服即有，而是日服 2016 年 7 月 5 日大更新加入，位于 SR 与 UR 之间。[武士道当年公告](https://prtimes.jp/main/html/rd/p/000000188.000014827.html)

用户记忆中的“UR 为 1%”对应加入 SSR 后、日服 2022 年 7 月调整前的经典特待生勧誘普通抽取概率：

| 稀有度 | 单次概率 | 说明 |
|---|---:|---|
| R | 80% | 该池的最低档；不是 N |
| SR | 15% | 高于 R |
| SSR | 4% | 高于 SR |
| UR | 1% | 最高档 |
| 合计 | 100% | N 不在这个池中 |

概率表见[当年的特待生勧誘资料及游戏内概率截图](https://xn--hckp3ac2l023wu2ve.com/tokutaisei-kanyu-ur-ssr-sr-kakuritsu.html)。2026-11-06，用户已确认商店采用上述四档及概率，包含 R，不包含 N。

日服 2022 年 7 月 5 日起，普通特待生概率改为 **R 76%、SR 15%、SSR 6%、UR 3%**。11 连的保底位置与活动池另有规则，不能把普通单抽表直接套到所有位置。[SIF 资料站：特待生勧誘及变更日期](https://w.atwiki.jp/lovelive-sif/pages/623.html)

### 有哪些勧誘

初代长期增加、调整过池子，不能用一个固定数字概括全部种类。为本商店讨论，主要区别可以归为以下五类；这些是整理口径，部分活动会叠加多种机制：

| 类型 | 核心区别 |
|---|---|
| 一般生勧誘 | 主要使用友情点，低稀有度为主；后期也有特定 SSR 转入生 |
| 特待生勧誘 | 通常使用爱心石或勧誘券，经典 R／SR／SSR／UR 池 |
| 限定／生日／阶梯／节庆勧誘 | 限定对象、概率提升或逐步奖励，具体活动各自规定 |
| BOX 勧誘 | 箱内卡片数量有限，抽走后剩余构成变化；不同于固定概率的无限池 |
| 补助券勧誘 | 使用补助券，分 SR／UR、SSR／UR、UR 保证及技能强化支援等入口 |

类别及机制参照[SIF 勧誘资料](https://w.atwiki.jp/lovelive-sif/pages/623.html)。没有把 μ's／Aqours 等不同对象池视为新的随机算法，也没有把活动名称逐个计数。

常见补助券成员池的历史参考：

| 消耗 | 抽取结果 |
|---|---|
| 5 张补助券 | SR 80%、UR 20%；不出 SSR |
| 10 张补助券 | SSR 80%、UR 20% |
| 25 张补助券 | UR 100% |

SSR／UR 与 UR 保证两种入口在 2017 年四周年活动加入，见[KLab 官方公告](https://prtimes.jp/main/html/rd/p/000000095.000006348.html)；具体概率及消耗见[补助券资料](https://w.atwiki.jp/lovelive-sif/pages/623.html)。技能强化支援池抽的是养成素材，不能与上述成员池混为一谈。

## 商店的两阶段抽取

用户已明确的顺序：

```text
花游戏内货币购买
    → 抽稀有度
    → 从该稀有度的物品池抽具体内容
    → 获得彩蛋奖励
```

稀有度概率与档内物品概率分开。2026-11-06 用户确认：**第一层使用 R 80%、SR 15%、SSR 4%、UR 1%；第二层在抽中的稀有度内，对各件物品等概率抽取。**

若某档有 n 件候选物品，则该档内每件物品的概率为 1/n。某一物品的最终概率为：

`P(物品) = P(所属稀有度) ÷ 该档候选物品数`

例如，UR 档若有 10 件候选物品，每件的总概率就是 1% ÷ 10 = 0.1%；10 件仅为示例，并非已定清单。新增 UR 物品会重新分配 UR 档内部的机会，不改变 UR 总概率 1%。不要把所有档的物品直接混成等概率大表，否则各档概率会随物品数量变化，偏离用户提出的顺序。

固定概率抽取中的 1% 不代表购买 100 次必出一次；保底或有限 BOX 是另外的机制，目前均未决定采用。也未确定购买后立即开奖，还是先获得可稍后打开的实体盲盒。

## 尚未确定的设计参数

以下仅标明构想空缺，不是自动创建的待办或默认实现方案：

- 具体命令名称、购买交互，以及是否需要菜单。
- 每次价格、使用哪一种现有货币及面额。
- 各档具体彩蛋物品及每项奖励数量；这是接下来讨论的内容。
- 是否允许重复抽得同一物品。
- 是否有多种商店池、限定物品、连抽、保底或其他 SIF 衍生机制。
