## 已批准接口

共同前缀 `/trainresync debug`；游戏内带 `/`，screen 内服务器控制台省略 `/`。权限等级 2，支持 OP 与服务器控制台。`<列车>` 接受完整 UUID 或精确名称，带空格的名称加引号；支持补全，重名时提示改用 UUID，不自动选一列。

| 指令（下表省略共同前缀） | 输出／作用 |
| --- | --- |
| `list [关键词]` | 以名称包含关系过滤，逐列显示完整 UUID、名称、运行状态、目的地，便于从控制台选择列车。 |
| `info <列车>` | 当前图 ID、车厢数、前后端维度／坐标、速度／目标速度、方向、燃料 tick、前后司机条件、手动控制、脱轨／等待区块、时刻表状态／当前项、目的地／剩余距离。 |
| `path <列车>` | 按顺序显示当前保存的分岔路径条目、两端坐标和维度、是否仍存在于当前图；显示当前车端所在边。该列表不是沿途每一块轨道，也不凭空路径判定故障。 |
| `signals <列车>` | 当前占用和预留区间、阻挡信号位置／类型／方向、等待距离／tick、连锁信号待预留组；列出相关区间的占用列车、预留信号及已解析冲突区间，未解析的引用明确列为未知，不调用会改变缓存的计算入口。 |
| `check [列车]` | 指定一列或检查全部列车的当前内存引用：列车的图是否仍是注册图、车轮所在边／规划边是否属于该图、目的地和信号引用是否存在。列出可定位的异常对象并汇总计数；不自动修复，不将无时刻表、正常脱轨无图、空剩余分岔路径或未预留当成异常。 |
| `at <维度> <x> <y> <z>` | 读取已加载位置的方块状态；轨道的曲线连接、Create 信号机／站台当前缓存的图绑定及目标轨道、信号状态／红石强制红灯／相关占用，以及该格和附近 8 格内的图节点与连接。无附近图节点不等于无轨道，长直线中段可能没有节点。区块未加载则明确 loaded=false，不为查询加载区块或重建绑定。 |
| `trace <列车> [秒数] [file]` | 默认 60 秒，范围 1–86400 秒，同时只跟踪一列。加 `file` 时须指定秒数，详细记录只写独立文件；线上 p-diag3 尚不支持 file，仍限 300 秒。开始时记录完整查询快照；运行中每秒最多一条状态摘要，并记录真实分岔选择事件。重新调用替换跟踪目标。 |
| `stop` | 结束当前跟踪。到期、目标被移除或服务器停止时也结束；不跨重启恢复。 |

`trace` 不带参数时只显示当前跟踪目标和剩余时间，不新增状态命令。`check` 复用 info／path／signals 的数据访问与格式化；`at` 将位置关联回既有图／信号报告，不另建诊断框架。所有查询读服务端当前状态，不能单靠这些接口证明客户端显示、所有地图区块或历史存档完全正确。

## 跟踪信息与输出位置

查询仅回复命令发起者；控制台发起则直接显示在 screen。默认持续跟踪写服务器原有 `logs/latest.log`，在控制台可见；加 `file` 后详细记录只写 `logs/trainresync-debug.log`（滚动规则见顶部），不进入控制台或 latest.log。不向所有玩家广播，不新增后台线程；开始／结束及状态查询只回复执行者。

跟踪记录：服务器 tick、列车 UUID，运行／时刻表状态、目的地、速度、所在位置、占用／预留组和阻挡信号变化；实际过分岔时记录位置、规划下一条边、候选边、实际选择、路径是否消费，以及选择依据 `planned`／`empty_path`／`planned_edge_unavailable`。信号探测器与实际车轮使用同一选择函数，必须区分两者；仅记录探测器选择不匹配的变化，避免每 tick 重复刷同一段预演路线。开始与结束输出一次完整快照，便于与事件串联。

此外逐事件记录导航开始、失败和取消（原方法执行前后的目的地／路径及返回结果），以串联“为何不再有规划路径”。不为推测调用原因采集调用栈。图对象／图 ID 和占用／预留等变化随每秒状态摘要记录，该采样可能合并一秒内多次变化，不宣称覆盖每次图编辑或信号计算。真实分岔与导航生命周期事件独立记录，不受每秒状态采样限流影响。

输出格式（示例字段，完整动态字段按上表展开）：

```text
[TrainDebug] LIST id={uuid} name="{name}" state={state} destination={uuid:"station"|none}
[TrainDebug] INFO name="{name}" id={uuid} graph={uuid} ...
[TrainDebug] PATH index={n} edge={from}->{to} exists={true|false}
[TrainDebug] SIGNAL group={uuid} occupied={trains} reservedBySignal={uuid|none} ...
[TrainDebug] CHECK trains={count} findings={count}
[TrainDebug] FINDING train={uuid} kind={kind} detail={value}
[TrainDebug] AT dimension={dimension} pos={x,y,z} loaded={true|false} block={state|unknown} ...
[TrainDebug] STATE tick={tick} id={uuid} ...
[TrainDebug] NAV tick={tick} train={uuid} event={start|failed|cancel} before={destination=... path=...} after={destination=... path=...} result={number}
[TrainDebug] FORK tick={tick} train={uuid} at={position} planned={edge|none} options={edges} selected={edge} reason={reason}
[TrainDebug] SCOUT_MISMATCH tick={tick} train={uuid} ...
跟踪：{名称}（{秒数} 秒）
正在跟踪：{名称}（剩余 {秒数} 秒）
跟踪结束：{名称}（{手动|到期|列车移除|服务器停止|切换目标}）
```

带 `[TrainDebug]` 的记录仅在执行对应查询／启用跟踪后输出；中文反馈只在实际触发的命令或跟踪结束时显示。查询不会自动开启持续日志。无对象／无目的地等正常状态用 `none`，未能判定用 `unknown`，不把缺值当作异常崩溃。新增 CHECK／FINDING／AT 查询也只回复执行者；NAV 跟踪事件沿用本轮选定的日志去向，trace 状态反馈只回复执行者。

## 实现边界

- 正式功能独立文件，与限额 JFR 和 RailwayMemoryDiagnostics 临时功能分开；可保留到常规版本，不依赖 1.6 炼药锅 pack-id。
- 指令使用 Forge 既有注册事件和 Create 内存对象；少量访问器读取非 public 字段。用小型 Navigation Mixin 观察原始分岔决策和导航生命周期，原方法只调用一次并原样返回结果，不自行寻路或修正轨道。
- 所有采样在服务器线程进行；不序列化整列车 NBT，不扫描全部世界、不强制加载区块、不复制 Create 导航算法，不引入后台采样框架。未开启 trace 时不建立快照或格式化日志。
- 只做权限、参数与目标生命周期等实际需要的处理，不为未知版本泛化、增加静默降级或重复校验。实现与测试结束后报告；部署、启动两服及看门狗、连接 screen 等待用户另行批准。
