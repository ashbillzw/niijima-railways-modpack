## 1. Meituan：配送接单（设计稿，尚未实现）

以下两个命令来自[货币获取与创作奖励构想](../玩法与配置/货币获取与创作奖励构想.md)，在本次核对的三个源码工作树中均未发现注册，不计入已有命令数量。

| 设计中的命令 | 已讨论的用途 | 状态 |
| --- | --- | --- |
| `/meituan jiedan` | 展示 5 个订单供选择；以系统随机订单为主，也可显示玩家发起的订单 | 尚未实现；正式接取某一单的交互待定 |
| `/meituan xiadan` | 使用执行者当前位置生成随机内容的订单，进入 waitlist；只替换自己仍在池中的旧单 | 尚未实现；已接订单绑定接单者，后续下单不影响它 |

设计时可参考的现有结构：

- 服务端命令通过 Forge `RegisterCommandsEvent` 注册；已有调试树使用 Brigadier 参数及补全。配送需要玩家位置、库存及订单归属，应在服务端判定，不能仅依赖 Legacy 客户端命令。
- 调试权限放在 `debug` 子树上。配送面向普通玩家，其权限应单独设计，不能直接继承 OP 2 要求；现有 `/meituan` 命名先保留，不因本表整理而迁到 `/trainresync debug` 下。
- 调试器的全服单一 `active` 跟踪状态不适合直接作为多人配送订单模型；配送已约定待接池和绑定接单者的订单分开处理。
- 后续设计仍以玩法构想为准：交付方式、列表刷新、同时接单数量、每日额度及结算规则均未定。本轮只整理接口依据，不增加命令、不接入玩家文案，也不新增待办。

## 2. TrainResync Debug：列车调试

本类命令共同使用 `/trainresync debug` 前缀，要求服务端权限等级 **2**，支持 OP 和服务器控制台。普通玩家不能使用这些调试子命令。

`<列车>` 支持完整 UUID 或精确名称，提供补全；名称含空格时使用双引号。重名必须改用 UUID。名称精确匹配区分大小写；`list` 的关键词是区分大小写的子串筛选。查询结果仅回复执行者。

### 列车信息与导航查询

| 完整命令 | 作用 |
| --- | --- |
| `/trainresync debug list` | 列出全部列车的名称、UUID、时刻表状态及目的地，按名称排序 |
| `/trainresync debug list <关键词>` | 按名称包含的关键词筛选列车；关键词可包含空格 |
| `/trainresync debug info <列车>` | 查询轨道图、车端位置、速度、目标速度、燃料 tick、司机、手动状态、脱轨、等待区块、时刻表及目的地等 |
| `/trainresync debug path <列车>` | 查询当前保存的分岔路径、对应图引用及边是否存在；不是沿途每格轨道的完整清单 |

### 信号、引用一致性与位置检查

| 完整命令 | 作用与边界 |
| --- | --- |
| `/trainresync debug signals <列车>` | 查询占用和预留区间、阻挡信号、等待状态、强制红灯及已解析的冲突区间；未解析的信息保留为 unknown |
| `/trainresync debug check` | 检查全部列车的轨道图、车轮、路径、目的地及信号引用，报告发现数；不修复 |
| `/trainresync debug check <列车>` | 对指定列车做相同检查 |
| `/trainresync debug at <维度> <x> <y> <z>` | 查询已加载方块、已有方块实体的绑定及附近 8 格内图节点；不加载区块、不创建方块实体、不重建绑定 |

`check` 的零发现不能证明历史存档及所有未加载世界方块均正确。`at` 使用 `DimensionArgument` 和 `BlockPosArgument`，与配送设计中的 X/Z 平面坐标不是同一种参数形式。

### 持续跟踪与日志

| 完整命令 | 作用 |
| --- | --- |
| `/trainresync debug trace` | 查询当前跟踪目标、剩余时间及文件模式状态；不会开始新跟踪 |
| `/trainresync debug trace <列车>` | 开始跟踪，默认 60 秒，详细记录进入既有控制台及 `logs/latest.log` |
| `/trainresync debug trace <列车> <秒数>` | 指定跟踪时长；本地新版允许整数 1–86400 秒 |
| `/trainresync debug trace <列车> <秒数> file` | 详细记录仅写入 `logs/trainresync-debug.log`；使用 `file` 必须先提供秒数 |
| `/trainresync debug stop` | 停止当前跟踪；没有正在运行的跟踪时返回状态 |

- 跟踪状态在服务端全局共享，同一时间只跟踪一列车；新的跟踪会结束原跟踪。不是每位玩家各自持有一份跟踪任务。
- 跟踪开始、结束生成完整快照；持续状态每秒至多一条，并观察导航及分岔等事件。所有观察沿用服务器线程，不创建后台采样线程，不修改导航结果。
- 到期、切换目标、目标被移除或服务器停止时清理跟踪。具有相同权限的其他执行者也能查询、替换或停止当前跟踪。
- 文件模式不把详细记录发到控制台或 `latest.log`；开始、结束和显式状态查询仍向相应执行者反馈。由其他执行者停止时，原发起者也收到结束反馈。
- 文件日志使用 UTF-8，按 32 MiB 滚动，保留 3 份 gzip 历史；当前文件追加写入。完整机制和历史验收见 TrainResync 仓库 `agent/列车调试.md` 及[整合包侧记录](列车调试指令方案-20261105.md)。
- 历史线上 `p-diag3` 的 300 秒限制及无 `file` 状态见开头版本表，不能套用本地新版语法。

## 3. Legacy / Deprecated：早期客户端列车刷新

按本次要求将最早的四个命令归入此类。它们在已核对源码中仍然注册；此分类不表示已经删除、禁用或具有 Java `@Deprecated` 标记。

共同条件：客户端安装对应 TrainResync；注册入口未设置 OP 权限要求。它们操作本地客户端状态，不是服务端列车管理命令。

| 命令 | 当前行为 | 边界 |
| --- | --- | --- |
| `/shuaxin` | 手动触发客户端车厢位置重同步 | 遍历当前客户端渲染实体，将车厢临时移到玩家下方以促使位置更新；不修复服务端轨道、路径或存档。需要处于世界中 |
| `/xuebaobizui` | 关闭普通列车刷新提示 | 默认已经为静音；强制反馈与调试消息不受此开关抑制，自动刷新功能仍运行 |
| `/verbose` | 开启普通列车刷新提示，使用详细提示模式 | 与静音模式相对，不是全模组或服务端的详细日志开关 |
| `/trainresyncdebug` | 开启客户端刷新计时、检查队列长度及提示状态的持续显示 | 只把调试标志设为开启；当前没有配套关闭命令，也不是 `/trainresync debug` 的别名 |

源码：`ClientInit.onClientCommandRegister`、`resyncAllCarriages`、`silentMode`、`verboseMode`、`debugMode`、`showMessage`。原有简表位于 TrainResync 仓库 `README.md`。
