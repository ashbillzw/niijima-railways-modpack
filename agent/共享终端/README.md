# 共享终端：工作流程、使用规则与协作习惯

整理日期：2026-10-25。适用于 AshBill 与助手共同操作本机 Windows 终端及其中的 SSH 会话。本目录收录本次实际使用的 v5 实现；它是维护工具，不属于整合包运行资源。

## 组成与范围

浏览器中的 xterm.js 负责显示和输入；Python HTTP 服务通过 pywinpty 管理同一个 Windows PTY，默认启动 `cmd.exe /Q`。用户与助手最终都向这个 PTY 输入，并读取同一份输出。它不是另开一条助手专用 SSH，也不是 Codex 内置终端的输入接口。

| 文件 | 用途 |
| --- | --- |
| `server.py` | 回环 HTTP 服务、认证、PTY、输出缓存及输入仲裁 |
| `client.py` | 助手读取状态、发送文本或命令文件 |
| `input_gate.py` | 用户输入状态、待确认命令与重复确认保护 |
| `index.html`、`app.js` | 共享终端页面、开关与确认框 |
| `static/xterm.js`、`static/xterm.css` | 已使用的终端渲染资源，支持 ANSI 颜色 |
| `static/LICENSE.xterm.txt` | 从现有 CSS 版权头提取的 xterm.js MIT 许可文本 |
| `requirements.txt` | Python 依赖：pywinpty 3.1.0 |
| `test_input_gate.py` | 输入门控单元测试 |
| `test_live.py` | 独立测试会话的 HTTP/PTY 集成测试 |

未收录：`session.json`、SSH 私钥、密码、DNS API 凭据、证书、终端输出日志、证书/NAS维护脚本、旧历史 README、编译缓存和平台专用 vendor 二进制。不得整目录复制原临时工作区入库。

## 启动与连接

### 本机环境

要求 Windows、Python 3.10 或以上；原运行环境为 Windows 11 / Python 3.13。新机器需安装与 Python/架构匹配的 pywinpty，不能直接搬用旧机器的二进制包。推荐在独立运行目录复制本目录，以免会话文件与临时命令混入源码。

以下命令均在共享终端程序目录下执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -X utf8 server.py
```

也可使用已有、已经安装依赖的 Python。`server.py` 会优先查找同级 `vendor/`，不存在时使用正常 Python 包搜索路径。本次归档不更改该行为。

服务只绑定 `127.0.0.1`，端口每次随机分配。不要把历史端口当作固定地址，也不要绑定到公网或局域网地址。启动进程需保持存活；结束进程会关闭 PTY 和其 SSH 连接。

### 打开页面

用户偏好（2026-10-29 确认）：提到“共享终端”或“智能共享终端”时，指本项目的浏览器版自研终端。默认在 **Codex 内置浏览器**中打开其网页，让用户与助手操作同一个 PTY／SSH 会话；不要误开 Codex 内置终端，也不默认交给系统外部浏览器。只有用户明确指定其他方式时才改用。

启动后，程序在同目录生成 `session.json`，包含 `url`、`ui_token`、`agent_token`。浏览器首次打开的地址格式为：

```text
<url>/#<ui_token>
```

由助手在内存中读取 session 文件，通过 `open_in_codex` 的 `target.type="browser"` 在 Codex 内置浏览器打开上述地址（不是 `target.type="terminal"`），或使用内置浏览器工具打开；不要把带令牌的真实链接贴到聊天、报告或 Git。页面将 UI 令牌存入 sessionStorage，再清除地址栏中的 fragment。

地址打开工具返回 queued 只代表已请求打开，不能当作用户已看到页面或已完成认证。确认页面可读后再继续。新服务会生成新令牌，旧页面/旧端口不能复用。

### 连接 SSH

本次使用用户已配置的别名；换机器先确认别名存在，不复制私钥或臆造连接配置：

```text
ssh -o StrictHostKeyChecking=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3 custom-sz-cn
```

SSH 私钥口令和后续 sudo 密码由用户直接在终端输入，不通过聊天传递。SSH 登录与 sudo 授权是两个步骤。等待口令时不能继续发送 shell 命令；用户说“已输入”后先读取终端结果，确认远端提示符再行动。

## 助手操作流程

使用与服务端对应的 Python，并开启 UTF-8，避免中文输出被 Windows 默认编码破坏：

```powershell
python -X utf8 client.py read
python -X utf8 client.py read --after 123
python -X utf8 client.py send '只读命令'
python -X utf8 client.py send --command-file command.txt
```

`--after` 使用上一次响应中的 cursor；服务重启后游标重新开始，应重新完整读取。`--session-file` 可选择不同会话。命令文件路径相对于调用时工作目录；会话文件默认相对于 `client.py` 所在目录。

每次发送前遵循以下顺序：

1. 读取当前状态，确认这是预期 SSH 连接、远端主机和用户，而非本机 CMD、密码框、screen 内的游戏控制台、ncdu 或分页器。
2. 检查已有 pending 和用户输入状态。先处理现有待发命令，不提交第二条去覆盖它。
3. 对非只读远端操作，完成下节要求的解释和选项审批。
4. 发送命令，读取返回状态；`sent` 只是交给 PTY，不等于执行成功，`queued` 是未执行。
5. 读取实际输出、退出/完成标记及服务/文件状态。进程启动不等于服务就绪；Minecraft 必须结合本次启动日志的 Done 和监听端口。

**读取与发送是有依赖的操作，必须先看读取结果再决定是否发送。** 不要将两者放在一个不检查结果的连续工具调用里。本次发生过 SSH 已退回本机而命令误入 CMD 的问题，不能依赖上一次的连接状态；一次读取也不能完全消除读取后断线的竞态。

## 当前界面与防撞规则

界面标题和网页标题均为「共享终端」。按钮、开关和状态尽量简短；额外解释放在提示或聊天，不堆在前端。

| 情况 | v5 行为 |
| --- | --- |
| 「全部允许」未勾选（启动默认） | 所有助手命令进入同一个待确认框，展示命令内容 |
| 「全部允许」勾选，且无用户输入冲突 | 新命令直接发送 |
| 勾选时已有待确认命令且无冲突 | 立即发送这条待确认命令 |
| 用户有未完成输入 | 即使勾选「全部允许」，助手命令仍等待确认 |
| 点击「发送」 | 发送待处理命令，不附加 Ctrl+C |
| 点击「覆盖」 | 先发送 Ctrl+C，再发送命令，可能中断前台程序 |
| 点击「丢弃」 | 删除待处理命令，不执行 |
| 关闭「全部允许」 | 后续命令要求确认；不会丢弃已排队命令 |

当前后端只有**一个待处理槽位**，不是多命令队列。已有 pending 时第二条命令返回 busy/HTTP 409；重复确认旧 ID 被拒绝。排队返回 HTTP 202。用户手动输入本身不受「全部允许」限制，助手读取也不受影响。

用户要求：点击终端下半部分空白区域也能聚焦输入。当前容器延伸至窗口底部，并绑定点击聚焦；有选中文字时不抢焦点。前端保持原有 110×32 终端尺寸，未实现随窗口动态调整行列。

旧的「仅我操作（暂停助手读写）」和「仅用户输入」模式已废弃。不要用旧文档描述当前行为，也不要为了测试擅自切换用户正在用的授权开关。

### 防撞的实际边界

- 服务端只保留输入活动标记，不保留用户逐键输入字符串。回车、换行、Ctrl+C 清除标记；退格、方向键等保守地视为有输入。
- 已识别的终端设备响应、光标报告、焦点和颜色响应不算用户编辑，防止空行误触发。
- ncdu 等交互程序的方向键仍可能留下输入标记。确认框出现不等于用户真的编辑了 shell 命令，也不等于 SSH 正在忙。
- 未完成输入检测不解析完整 shell；不能判断命令是否运行中、输入是否密码、SSH 是否已断开，也不能识别远端主机。
- 「覆盖」不是总能安全打断程序的保证；不要替用户点击确认或利用 UI 令牌绕过门控。
- 网络事件存在先后竞态；用户尚未到达后端的按键不会提前被门控识别。

## 远端操作授权规则

这是用户在本次服务器维护中明确规定的规则，使用本共享终端维护该服务器时沿用：

- 对确信只读、不修改远端文件或状态的命令，可直接检查并说明结果。
- 任何远端状态变更前，先解释命令作用、具体影响路径或服务，再用选项框取得明确 approval。包括写配置、复制/移动/删除、DNS修改、服务启动/停止/重启及改变会话环境。
- 「全部允许」只控制终端输入门控，**不等于免除聊天中的远端操作审批**。
- 用户在选项回复里对具体操作的明确批准持续有效；断线重连无需重复审批相同范围。范围改变或新增动作需说明并取得相应授权。
- 用户限定“先复制”“只校验”“不要启动”“暂留副本”时逐阶段执行，不把完整计划当作所有阶段已授权。
- 用户说“停止”后停止推进，先确定是否有任务正在运行或排队；需要中止现有任务时明确对象与影响。不能把停止读取输出当作停止复制，也不要误报远端状态。
- 密码、密钥口令由用户输入。不要以网络重连、脚本编码或独立 SSH 绕过上述流程。

## 已确认的使用习惯

- 默认使用 Codex 内置浏览器中的自研共享终端网页，用户能看到输出并亲自输入；需要颜色渲染。（2026-10-29 明确）
- 用户喜欢短界面文案：「共享终端」「全部允许」「发送」「覆盖」「丢弃」。解释仍应保留影响决策的关键信息。
- 用户正在输入时，助手命令应展示内容让其决定；不是一律拒绝。勾选「全部允许」后应释放无冲突的待处理命令。
- 复制等长任务需要可见进度、速度和预计剩余时间；如实际只在文件结束时刷新，要如实说明，不能宣称每秒更新。
- 可以提交 Base64 等编码脚本，但必须同步在聊天解释解码后的用途、路径、修改/删除范围，并提供可读源码。编码不是加密，也不能把凭据藏在其中认为安全。
- 喜欢先规划、讨论、批准再执行，尤其迁移、删除和停启服；保留原有目录结构与命名规律。
- 不为纯注释修改默认创建无意义备份；按实际回退需要决定。不要据此推断重要数据操作也不需要回退方案。
- 不要把流程做得比实际需要更复杂；先考虑现成工具和官方功能，额外脚本要解释用途。
- 完成后简洁报告实际结果与未验证范围；不能把发送、启动、校验通过、上线运行混为一谈。

这些条目整理已有会话约定，不将本次端口、服务器容量、审批或数据路径推广成其他项目的永久授权。

## 断线与恢复

区分三种状态：

1. **SSH 断开，本机终端仍在。** 输出出现 disconnect/closed，提示符回到 Windows 路径。不要再发 Linux 命令，重新登录并等用户输入口令。
2. **本机共享服务停止。** client 访问回环端口报 connection refused。旧页面无法恢复该进程；重启 `server.py`，读取新 session，打开新地址，再登录 SSH。
3. **长命令输出暂时没有刷新。** 不等于断线，也不等于完成；读取输出并等待，不重复提交可能重复复制/写入的命令。

API 的 `alive` 仅表示本机 PTY 进程存活，不是 SSH 或 Minecraft 存活证明。输出缓存有限，历史内容会被淘汰；缺输出时需用只读状态/日志核实，不凭猜测重试。发现断线后不要立即强制重建还活着的终端。

重启共享终端会断开其 SSH；会影响前台远端任务，不能把工具升级当作无影响刷新。用户已批准重启时可执行，否则先解释并确认时机。纯页面刷新不会主动重启后端。

## 颜色与凭据边界

新 PTY 环境设定 `TERM=xterm-256color`、`COLORTERM=truecolor`。xterm.js 解释 ANSI 控制码，client 的 JSON 中看到转义字符是正常的。若远端仍为 `TERM=dumb`，应诊断当前会话；不要擅自覆盖远端永久 PS1 或启动文件。

服务不写终端日志，输出仅保存在内存；但 shell 回显、工具返回、命令历史以及第三方程序仍可能记录内容。因此不能声称“密码绝不会泄露”。不要发送带秘密的明文命令，不要完整展示 session 文件，不要将敏感输出入库。

UI 和助手使用不同令牌；UI 能切换开关及确认，助手接口不能。令牌以明文存放本机 session 文件，当前实现未专门设置 Windows ACL，它不是抵御本机恶意程序的隔离系统。正常退出会删 session 文件；异常终止可能残留。运行目录应为用户私有目录，session 文件必须忽略，不转发该 HTTP 服务。

## 验证与维护

单元测试：

```powershell
python -m unittest test_input_gate.py
```

集成测试必须使用**独立的本机测试会话**，不得对用户正在工作的正式会话运行：

```powershell
# 窗口一：服务持续运行
python -X utf8 server.py --session-file session-test.json
# 窗口二：同目录，测试最后会关闭这个测试会话
python -X utf8 test_live.py
```

`test_live.py` 使用测试会话的 UI 令牌模拟确认流程，不能改成读取正式 `session.json`。它检查默认确认、队列释放、冲突保护、丢弃、重复确认和仅 UI 可切换开关。前端可用 `node --check app.js` 做语法检查；语法通过不等于视觉或点击验收。
