## 4. SSI 的最小实现边界（示意，不实施）

```text
dist/                          → /var/www/minecraft-backup/v3/
  index.html                  主页：活动banner＋地图切换
  _includes/header.html        共用顶部HTML
  _includes/footer.html        共用底部HTML
  assets/site.css              复用现有公共样式
  events/index.html            跳转入口，无公共栏
  events/feedback-v1.6/index.html
  feedback/index.html
  backups/index.html          后续独立备份日历页（仅规划）
```

内容页用：

```html
<!--# include virtual="/v3/_includes/header.html" -->
<main>页面自己的内容</main>
<!--# include virtual="/v3/_includes/footer.html" -->
```

- 只在Nginx `/v3/` 范围开启 `ssi on`，明确该location的root为 `/var/www/minecraft-backup`（旧配置root位于location /内，不能假设兄弟location继承）。保持旧站和NAS下载规则不变。
- Nginx SSI默认处理text/html，`.html`可继续使用，无须改名.shtml。header/footer中的图片和链接采用明确的`/v3/`或站点根URL；浏览器会按最终页面地址解析片段内相对路径，不按片段文件路径解析。
- Nginx在响应中组合片段，浏览器收到完整HTML；不引入Vue，不新增构建流程，不用fetch二次加载顶栏。公共样式仍为site.css。简单下拉优先使用原生details/summary；没有明确需求就不添加额外交互脚本或单页路由。
- SSI解决HTML复用，栏目选中可由页面的data-section及公共CSS表达；不为此创建菜单API、状态管理或多套组件框架。
- 不把页面标题/meta机械合并成一个固定head，每页保留自己的标题和活动样式。没有新增可见文字放进程序默认错误提示；异常文案若需自定义，实施时另按规则审核。
- SSI响应默认移除原HTML的Last-Modified；不为了缓存随意开启ssi_last_modified，因为片段也会独立更新。验收需检查实际响应和刷新，而不只检查源文件。
- 普通Python http.server不解析SSI，因此现有预览.cmd不能直接用于验收共用栏。实施时需要支持SSI的本地预览环境；不要为了预览在源码中再维护一份复制的顶栏。当前服务器SSI模块是否可用尚未核查，部署前再只读确认。

参考：[Nginx官方SSI模块文档](https://nginx.org/en/docs/http/ngx_http_ssi_module.html)。

## 5. 独立备份日历页（2026-11-10用户要求，仅设计）

入口拟为 `/v3/backups/`，从独立顶栏「备份」进入。旧备份.html和现有下载URL先保持不动。

已确定的展示规则：

- 自动读取短期与长期备份列表，不手填日期与文件大小。
- 从当前数据中最早备份所在月，一直排到最新备份所在月，逐月连续渲染真实日历，按时间先后排列。
- 中间整月没有残余备份也必须显示，不跳过空月；不能只展示有备份的月份。
- 有备份的日期用橙色格子，格内显示GB数；没有备份的日期用灰色格子。范围按现存备份推导，不承诺记录已经全部淘汰的历史边界月份。
- 此页是备份展示/下载入口，不修改现有短期备份和长期归档保留规则，不触发创建或删除备份。

后续设计需明确但本轮不预设的细节：两服的分组/切换方式；同日多份备份的GB数展示与点击展开方式；短期和长期中同一份硬链接备份的去重规则；日期采用的时区与数据来源（备份时间，不能直接把迁移时间当作备份日期）；GB与GiB的换算口径；列表的生成/获取方式。现有归档采用硬链接，容量展示应区分备份文件大小与实际占盘，不将双入口简单相加当成物理占用。

这些是实施前待讨论的设计细节，不自动写入todo，不新增后台服务或定时任务。本轮不实现页面、不读取或改写远端备份。
