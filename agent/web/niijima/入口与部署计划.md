## 1. 公开网页存储在 Synology，独立于 copyparty 界面

已有 `PrismLauncher/agent/copyparty镜像准备.md` 记录：正式下载根为 `https://mc1.ashbill.com:25572/synology-root/minecraft/niijima-launcher/`，服务端路径为 `/synology/MCShare/minecraft/niijima-launcher/`。本机既有 nginx 配置快照也包含 `location /synology-root` → `alias /synology/MCShare`。因此优先沿用 nginx 直接提供 Synology 文件的方式，不需要通过 copyparty 的浏览页面来展示网站。

拟将本目录 `dist/` 的内容部署至：

```text
/synology/MCShare/minecraft/niijima-launcher/web/
  feedback/index.html
  events/feedback-v1.6/index.html
  events/index.json
  activity/index.html
  config/activity.json
  config/site.json
  assets/...
```

拟议公开根：
`https://mc1.ashbill.com:25572/synology-root/minecraft/niijima-launcher/web/`

网页、图片和 JS 存在 Synology，主机只用已有 nginx 提供服务；无需在主盘复制整套站点。上线前要现场核对挂载、权限、nginx 当前配置、HTML/SVG/JS MIME、HTTPS 和页面缓存，不能把旧快照视为已上线证据。配置 JSON 建议 `Cache-Control: no-cache`，资源更新后应能及时生效。

另一可选方式是 Synology 自己的 Web Station：官方支持 Static 网站和独立 Web Service Portal，无需 PHP 或数据库。若现有 nginx 映射可用，原型不必为此再开一套服务。参考：[Synology 建站说明](https://kb.synology.com/en-id/DSM/tutorial/How_to_host_a_website_on_Synology_NAS)、[Web Service](https://kb.synology.com/index.php/en-us/DSM/help/WebStation/application_webserv_webservice?version=7)。

## 2. FM 始终使用一个活动地址

拟配置：

```text
https://mc1.ashbill.com:25572/synology-root/minecraft/niijima-launcher/web/activity/?in_game=1
```

入口读取 `config/activity.json`：

```json
{"target":"../events/feedback-v1.6/"}
```

`target` 相对配置 JSON 地址解析，允许管理员配置 HTTPS 外部页面或相对路径；本地预览可用 HTTP。保持 `in_game=1` 传递。没有活动时设 `target` 为 `null`，转到 `feedback/`；配置读取失败同样回退至反馈页，防止空白加载停留。该逻辑已提供为网页原型，不是已修改整合包的 FM 界面。

活动页内 iframe 使用 `feedback/?embed=1&nav=0&event=feedback-v1.6`；若游戏内打开，再加 `in_game=1`。反馈页独立访问无需活动参数，不会因活动下线消失。部署时活动页和反馈页保持同源，避免额外跨域嵌入问题。上传后不得把私有日志文件链接作为公开内容展示。

## 3. 启动器活动按钮索引

默认固定 URL 拟为公开根加 `events/index.json`。示例已经随原型提供：

```json
{
  "schemaVersion": 1,
  "events": [
    {
      "id": "feedback-v1.6",
      "image": "../assets/feedback-banner.svg",
      "url": "./feedback-v1.6/",
      "alt": "v1.6测试期间Bug反馈/功能建议收集"
    }
  ]
}
```

- 数组顺序就是按钮从上到下的顺序；一项对应一张图片和一个目标 URL，不通过扫描目录推测活动。
- 启动器只从索引读取图片 URL 与目标 URL，取得图片后将该图片显示为可点击按钮，不另叠网页按钮、标题或外链符号；外链符号已经在图片里。按索引顺序显示于内容区右上角并向下排列，避开标题栏控件。反馈活动可以长期保留，其他活动通过增删／重排索引管理，不虚构截止时间。
- 用户确认活动按钮复用当前启动／下载按钮的比例与圆角。`PrismLauncher/launcher/ui/NiijimaHomeWindow.cpp` 的 `HomePrimaryButton::sizeHint()` 按 36px 字体的「启动游戏」字形和两侧 0.6 字边距计算；该仓库 handoff 2026-10-30 的既有离屏实测为 **221×81 逻辑像素（约 2.728:1）**，当前样式圆角 **10px**。本轮未启动或重新构建启动器。示例活动图改为 884×324（4 倍同一比例）的直角原图；将来 Qt 按钮以实际主按钮尺寸为基准，在渲染时裁 10 个逻辑像素的圆角（DPI 缩放由 Qt 处理），不能把圆角烘焙进原图。
- `image`、`url` 相对**实际读取的索引 URL**解析。使用本地索引时，相对图片和活动地址一并落在本地站点；不仍以生产 URL 为基准。
- 点击使用解析后的活动 URL 在浏览器打开。空数组不展示活动按钮；索引读取失败不影响下载／启动游戏。不擅自加错误弹窗或新的占位文案。
- 不使用整合包发布列表的“最大数字 ID”规则；活动可能同时存在多个。稳定的活动 ID 用于辨识，展示顺序只看数组。

## 4. 复用 niijima-local-test.json 的计划

本机源码 `launcher/niijima/LocalTest.h/.cpp` 当前只读取 `packs`、`mirror`、`testWarning` 等既有字段；`resolve()` 映射 `packs/` 与 `niijima-mirror/`。**现在并没有活动索引的重定向字段。** 本轮不改启动器源码或运行中的测试 JSON。

拟在同一份、EXE 旁的 `niijima-local-test.json` 新增可选字段：

```json
{
  "packs": "D:/mydata/Agents/Minecraft相关/本地资源/启动器整合包发布/packs",
  "mirror": "D:/mydata/Agents/Minecraft相关/本地资源/Prism镜像部署/niijima-mirror/publish",
  "eventsIndex": "http://127.0.0.1:18761/events/index.json"
}
```

不设置 `eventsIndex` 时用正式固定地址。设置时，活动加载器先取该值，再读取索引并以此解析资源与点击地址。采用本地 HTTP，而非将图片映射到磁盘却仍让浏览器访问生产页面。启动器沿用现有“启动时读取测试 JSON”的行为，修改后重启生效。

接入时把活动地址校验与既有 packs／mirror 校验分开：不改变已存在的包与镜像错误处理，也不让活动索引失败阻塞游戏主流程。若以后允许仅测试活动而不提供 packs／mirror，需显式支持该模式，不能把当前源码的必需字段检查直接删掉。新字段不得随正式安装器携带。

## 5. copyparty 仅负责私有收件

网页托管不依赖 copyparty UI，上传则用 copyparty 原生 HTTP API。配置留空，等之后连接服务器创建专用卷后填写。优先给网页同源的反代路径，指向 copyparty 的仅上传卷；也可跨域直连，但需按实际 Origin 配好 CORS。不得在前端放管理员密码。

**私有日志不要放在 `/synology/MCShare` 公共 alias 范围内。** 即使 copyparty 禁止下载，nginx 的公开映射也可能绕过它。应另选 Synology 私有共享目录／挂载，仅给 copyparty 服务读写及管理员读取，并配置匿名仅写、大小／总容量限制；具体路径在服务器现场确定。

用户已确认附件合计 10 MiB、最终 ZIP 11 MiB。服务端最终 ZIP 上限与网页 `maxArchiveBytes` 对齐为 11 MiB；nginx 请求体上限额外留 multipart 开销，不能比应用上限更小。卷总量、文件数量和存储硬配额沿用活动专题的讨论，不能仅靠前端或应用层容量承诺主盘不会被塞满。页面不读取上传目录内容，不需要给匿名用户读权限。
